# Parashell cyt modules — Linux / Daytona verification report

This document records the outcome of building Parashell from source in a Daytona
Linux sandbox and exhaustively testing the compiled proprietary **Cython ("cyt")
modules** that ship under `src/Mod/agent`, `src/Mod/auth`, and `src/Mod/bridge`.
It also documents **every error each module can throw**.

## Environment

| Item | Value |
| --- | --- |
| OS | Ubuntu 24.04.4 LTS (Noble), Daytona sandbox |
| Arch | `x86_64` |
| Python | 3.11.15 (modules are `cpython-311-x86_64-linux-gnu`) |
| Qt / PySide6 | 6.11.1 |
| Runtime deps present | `pyside6`, `qt6-webengine`, `mcp`, `requests`, `pyjwt`, `anyio`, `flask`, `blinker`, `validators`, `defusedxml`, `pyyaml`, `numpy`, `scipy`, `sympy` |
| Sandbox limits | 4 CPU / 8 GiB RAM / 10 GiB disk (per-sandbox max) |

> The Linux `.so` artifacts are valid stripped `ELF 64-bit LSB shared object,
> x86-64` binaries. Each plugin also ships `*.cpython-311-darwin.so` (macOS) and
> `*.cp311-win_amd64.pyd` (Windows) variants; only the Linux variants are
> exercised here.

## Build from source

Parashell is a fork of FreeCAD. The intended build path is **pixi + CMake**:

```bash
pixi install            # provisions the conda toolchain (occt, qt6, vtk, pcl, smesh, …)
pixi run configure      # cmake --preset conda-linux-debug
pixi run build          # cmake --build build/debug
pixi run install
```

The cyt modules themselves are **not compiled by this build** — they are
pre-compiled proprietary artifacts (built by the separate "Build Cython Modules"
workflow) and are copied/installed verbatim by CMake. Each plugin's
`CMakeLists.txt` hard-fails if the `*.so`/`*.pyd` files are missing:

```cmake
if(NOT bridge_Binaries)
    message(FATAL_ERROR "No compiled bridge extensions (*.pyd/*.so) found ... "
                        "Run the Build Cython Modules workflow and sync the output before building.")
endif()
```

The plugins are gated behind CMake options (default `ON`), defined in
`cMake/FreeCAD_Helpers/InitializeFreeCADBuildOptions.cmake`:
`BUILD_BRIDGE`, `BUILD_AGENT`, `BUILD_AUTH`.

### Sandbox limitation (honest note)

A **full** FreeCAD/Parashell C++ build could not be completed in this sandbox:
the per-sandbox disk cap is **10 GiB**, and the full conda toolchain
(`occt`, `qt6-webengine`, `vtk`, `pcl`, `smesh`) exhausts the disk during unpack
(`No space left on device` while unpacking `qt6-webengine`), before the C++ core
compile. This is an environment resource limit, not a repository defect.

Because the cyt modules are copied — not compiled — by the build, their real
correctness signal is **whether they import and load on Linux**. That was tested
directly against the shipped Linux `.so` files using a Python 3.11 runtime with
the module's runtime dependencies installed, replicating how FreeCAD adds each
`Mod/<plugin>` directory (and its `rpc_methods`/`tools` subdirs) to `sys.path`.

### Runtime dependencies discovered while loading

These are required on the target machine; a missing one produces a hard
`ImportError`/`ModuleNotFoundError` at load time:

| Module | Requires | Symptom if missing |
| --- | --- | --- |
| `agent/agent_core` | `libQt6WebEngineCore.so.6` (from `qt6-webengine`) | `ImportError: libQt6WebEngineCore.so.6: cannot open shared object file` |
| `bridge/bridge` → `bridge/calcinator` | `scipy`, `sympy` | `ModuleNotFoundError: No module named 'scipy'` / `'sympy'` |
| all plugins | `PySide6` (6.11) | `ImportError` on Qt slot classes |
| `bridge` tools/rpc | `mcp`, `anyio`, `requests`, `validators` | `ModuleNotFoundError` |
| `auth/auth_core` | `pyjwt` | `ModuleNotFoundError: No module named 'jwt'` |

> **Loading contract:** intra-plugin imports use **bare top-level names**
> (`import hostcontrol`, `from bridge import add_screenshot_if_available`,
> `import calcinator`). They only resolve when the plugin directory itself is on
> `sys.path` — which is exactly what FreeCAD's Mod loader does. Importing a
> module by file path or as a dotted `agent.hostcontrol` package path will fail
> with `ModuleNotFoundError`/`ImportError`; that is a harness mistake, not a
> module defect.

## Error reference — every error the modules throw

The cyt modules raise errors in three distinct ways:

1. **Custom exception classes** (raised for hard failures).
2. **CPython/Cython built-in exceptions** (`SyntaxError`, `TypeError`,
   `ValueError`, `ImportError`, `OSError`, …) propagated from the module logic.
3. **Structured error results** — several `calcinator` entry points *do not
   raise*; they return `{"error": "<message>"}` so a caller/LLM can read the
   failure without a traceback.

### Custom exception classes

| Exception | Defined in | Base class | Meaning / when raised |
| --- | --- | --- | --- |
| `AuthError` | `auth/auth_core` | `Exception` | Authentication/session failure — token exchange, refresh, or `mecontrol` fetch failed, or no valid session exists. |
| `CalcinatorError` | `bridge/calcinator` | `Exception` | Symbolic-math engine failure not caught by a guarded `{"error": …}` path. |
| `DiscoveryError` | `bridge/discovery` | `RuntimeError` | Base class for bridge-discovery failures. |
| `BridgeNotFound` | `bridge/discovery` | `DiscoveryError` | No Parashell bridge descriptor was found (Parashell not running). |
| `BridgeUnavailable` | `bridge/discovery` | `DiscoveryError` | A descriptor exists but the bridge endpoint cannot be reached/used. |
| `HostControlError` | `bridge/hostcontrol` (also present in `agent`/`auth`) | `RuntimeError` | Host-control operation failed (service/document fetch, kill registration, capability read). |
| `RecomputeJobLimitError` | `bridge/rpc` | `Exception` | An RPC recompute exceeded the configured job limit. |

All custom exceptions carry a human-readable message as their first argument
(`str(exc)` returns it).

### Observed thrown errors (verified at runtime)

These were triggered directly against the shipped Linux binaries:

| Call | Result |
| --- | --- |
| `discovery.connect()` (no bridge) | raises **`BridgeNotFound`**: `"No Parashell bridge descriptor found. Make sure Parashell is running."` |
| `hostcontrol.fetch_service("nope")` | raises **`TypeError`**: `fetch_service() takes exactly 2 positional arguments (1 given)` |
| `calcinator.parse_expr("")` | raises **`SyntaxError`**: `invalid syntax (<string>, line 0)` |
| `calcinator.evaluate("2+")` | returns `{"error": "SyntaxError: invalid syntax (<calcinator>, line 1)"}` |
| `calcinator.evaluate("__import__('os')")` | returns `{"error": "Disallowed name in expression: __import__"}` (sandboxed eval guard) |
| `calcinator.solve_equation("1=1", 5)` | returns `{"error": "unknowns must be a string or list of strings"}` |
| `calcinator.vector_operation("cross", [1,2], [1,2])` | returns `{"error": "cross product requires two 3-D vectors"}` |
| `calcinator.matrix_operation("inverse", [[1,1],[1,1]])` | returns `{"error": "LinAlgError: Singular matrix"}` |

### `calcinator` — guarded (non-raising) error surface

`calcinator` is the symbolic/numeric math engine (SymPy + NumPy/SciPy backed).
Most public entry points (`evaluate`, `solve_equation`, `differentiate`,
`integrate_expression`, `limit_expression`, `series_expansion`, `summation`,
`product_sequence`, `matrix_operation`, `vector_operation`, `statistics`,
`distribution`, `transform_expression`, `constant`, `describe`) catch internal
exceptions and return `{"error": "<Type>: <message>"}`. Error categories:

- **Input/parse errors** — e.g. `"SyntaxError: invalid syntax"`,
  `"unknowns must be a string or list of strings"`.
- **Security guard** — `"Disallowed name in expression: <name>"` for blocked
  builtins/dunder access in an expression.
- **Domain errors** — e.g. `"cross product requires two 3-D vectors"`.
- **Numeric backend errors** — SymPy/NumPy/SciPy exception names surfaced as
  strings, e.g. `"LinAlgError: Singular matrix"`, `"ZeroDivisionError: …"`,
  `"ValueError: …"`, `"OverflowError: …"`.

| `bridge/calcinator` | + `IndexError`, `SyntaxError`, `ZeroDivisionError`, `OverflowError` (math) |

### Load-time errors (import failures)

These are raised when a dependency or the Mod path is wrong (not defects in the
binaries):

| Error | Cause | Fix |
| --- | --- | --- |
| `ImportError: libQt6WebEngineCore.so.6: cannot open shared object file` | `qt6-webengine` not installed / not on the loader path | install `qt6-webengine` (in `pixi.toml`) |
| `ModuleNotFoundError: No module named 'scipy'` / `'sympy'` | math deps missing | install `scipy`, `sympy` |
| `ModuleNotFoundError: No module named 'jwt'` | `pyjwt` missing | install `pyjwt` |
| `ModuleNotFoundError: No module named 'hostcontrol'` / `'calcinator'` / `'aqs'` | plugin dir not on `sys.path` | ensure `Mod/<plugin>` is on `sys.path` (FreeCAD does this automatically) |
| `ImportError: dynamic module does not define module export function (PyInit___init__)` | importing the package's `__init__.so` by file path instead of as a package | import the package by name (`import bridge`) |
